# 审校记录 · 2026-11-03-quant-compile

## verdict

revise

## summary

八个结构件（自测/概念/例子/误区/总结/术语卡/下一步/来源）齐全，模块目标 1、3、4 覆盖到位，AWQ/GPTQ/SmoothQuant 的机制描述基本准确，权重误差、8.75 ms、114/228 token/s、1.6% 开销等数字重算均正确。但 worked example 有一处硬伤（6 维权重配 3 维激活，max 所在的 −1.24 根本没进点积），且 0.03% 的结论靠激活误差抵消，会教出错误的精度数量级；QAT 仅一句话，撑不起“区分 PTQ 与 QAT”的目标；另有 FP8 离群值方向、signed/unsigned 口径、硬件数字来源三处需要修。

## issues

### Issue 1

- severity: high
- claim: “把 6 个权重做对称 INT8 量化，再算一次点积。W = [0.12, −0.45, 0.83, −1.24, 0.02, 0.67]……激活 X = [1.0, −2.0, 0.5]”
- problem: W 是 6 维、X 是 3 维，点积维度对不上。整数累加 64·12 + (−127)·(−46) + 32·85 只用了前 3 个权重，后 3 个权重（−1.24、0.02、0.67）在算里凭空消失，而 max|W| = 1.24 恰恰来自这个没参与点积的权重；“真值 0.12 + 0.90 + 0.415”同样漏掉后 3 项。基础弱的读者照着手算会卡在“第 4 个权重乘什么”。
- fix: 二选一并同步重算第 3、4 步所有数字：①把 X 补成 6 维（保持 max|X| = 2.0，重算 s_x、q_x、整数累加、真值）；②把 W 缩成 3 个权重且让 max|W| 仍为 1.24（如 [0.12, −0.45, 1.24]）。推荐 ①，因为能顺带演示 6 个权重都被量化。

### Issue 2

- severity: high
- claim: “真值：0.12 + 0.90 + 0.415 = 1.435，相对误差约 0.03%”（配合第 3 步“最大绝对误差 0.0037，约 0.3%”）
- problem: 激活也被量化了，但讲义只报了权重误差。实际 q_x·s_x = [1.00787, −2.0, 0.50394]，第一个激活的误差是 +0.79%，比权重的 0.3% 大得多。拆开算：只量化权重 X·ŵ = 1.4304（−0.32%），只量化激活 x̂·W = 1.4392（+0.29%），两者方向相抵才凑出 −0.03%。把 0.03% 当成“量化链路的精度”会让读者建立错误数量级直觉，逐元素复算也复现不出这个结论。
- fix: 列出 x̂ 及其误差，分别给出“仅权重 −0.32% / 仅激活 +0.29% / 两者都量化 −0.03%”三个数，并点明最后的小误差是抵消巧合、不能外推；补一句“误差随数据分布变化，以自评测为准”。

### Issue 3

- severity: medium
- claim: “误区 3：量化感知训练（QAT，训练时插入伪量化节点模拟误差）总比 PTQ 好”（正文对 QAT 的全部展开仅此一段）
- problem: 模块目标 2 要求“能区分训练后量化与量化感知训练”，但 QAT 只出现在“误区”里的一句话，没有独立小节，也没有对照维度（数据量、算力、精度提升从哪来、什么时候必须上 QAT）；PTQ 也只点了名，没讲校准数据如何定量化参数。读者只能记住“QAT 更准但更贵”，达不到“区分”的目标。
- fix: 在核心概念里加一小节“PTQ vs QAT”左右对照（要不要训练、数据量、典型耗时、精度、能否处理 W4A4 或激活量化），用一句话解释伪量化节点与直通估计器在做什么，最后给“先 PTQ，不达标再 QAT”的决策路径。

### Issue 4

- severity: medium
- claim: “它对激活中的离群值特别敏感，精度比 INT8 更依赖数值分布。”
- problem: 方向存疑且写成了事实。FP8 保留指数位、逐元素是对数刻度，对离群值的容忍通常优于 INT8 的均匀刻度（这也是 W8A8-FP8 常不必配 SmoothQuant 的原因）；FP8 的真实限制是可表示范围窄（E4M3 最大约 448）与有效尾数仅 4 位（相对精度约 2⁻⁴ ≈ 6%），需要按张量/按块缩放把数值挪进范围。按现文读者会得出“INT8 比 FP8 更抗离群”的错误结论。
- fix: 改为“FP8 保留指数、动态范围表达优于 INT8，对离群值通常更宽容；但 E4M3 范围只有约 ±448、尾数仅 3 位（相对精度约 6%），必须靠缩放把数值挪进范围”。若坚持原判断，请给出处并标（存疑）。

### Issue 5

- severity: medium
- claim: “8 位、4 位定点整数，对称时取值范围分别是 [−128, 127] 和 [−8, 7]”；“s = max|x| / 127”；“s = (max − min)/255，z = round(−min/s)”
- problem: 三处互相对不上：对称方案只用 ±127（−128 码点永不出现），却把范围写成 [−128,127]；非对称公式的 q 落在 [0,255]，是 uint8 的域，与前面定义的“有符号 8 位”矛盾，读者会疑惑到底是 255 还是 256、零点为什么不是 −128。术语卡“对称范围 [−128,127]”同样受影响。
- fix: 统一口径：对称写 q ∈ [−127,127] 并注明 −128 不用；非对称二选一——q ∈ [0,255]（uint8 存储，z = round(−min/s)），或有符号版 q ∈ [−128,127]（s = (max−min)/255，z = round(−128 − min/s)），术语卡同步修改。

### Issue 6

- severity: medium
- claim: “以 1.6 TB/s 的 HBM 带宽算……单请求理论上限约 114 token/s”；“INT8……吞吐常是 FP16 的数倍”
- problem: 硬件数字没有来源和型号。1.6 TB/s 既不是 A100（2.0）也不是 H100（3.35），像是昇腾 910B，但正文没有说明；“数倍”与主流数据不符（多数 GPU/NPU 的 INT8 相对 FP16 约 2×，部分架构 4×）。同一段里昇腾 FP8 支持标了（存疑），这两条却写成事实，读者无法判断哪些能直接引用。
- fix: 注明“以昇腾 910B（约 1.6 TB/s）为例”并给出规格来源；“数倍”改成“约 2×（部分架构 4×，随芯片而定）”；凡昇腾相关性能断言统一加来源或（存疑）。

### Issue 7

- severity: low
- claim: “LLM 推理只有三个可动的旋钮：模型本身、硬件、以及「用什么精度算、用什么方式跑」。量化动第一个，编译动第三个。”
- problem: 按这个分类，量化明显属于第三类（精度/执行方式），说它“动第一个”自相矛盾；“只有三个”也被下一课的投机解码反证（解码策略/调度三类都装不下），读者会建立错误的心智模型。
- fix: 改成“量化动的是精度这一维，编译动的是执行方式这一维”；或把旋钮扩成四类（模型 / 硬件 / 数值精度 / 执行与调度），并说明投机解码属于第四类。

### Issue 8

- severity: low
- claim: “FP16 尾数多 3 位，相对精度约 2⁻¹¹”；“eager（PyTorch 默认的逐行解释执行）”；“缩放因子通常按张量或按通道算”
- problem: 面向基础较弱读者，几处首现术语未解释或解释失真：“尾数多 3 位”缺比较对象（比的是 BF16，但 BF16 还没出场）；eager 不是“逐行解释执行”而是即时执行/define-by-run；“通道”“动态范围”“离群值”“校准数据”在 AWQ/GPTQ/SmoothQuant 里首次出现就没有解释（要到术语卡才查得到），而它们正是理解这三种方法的关键。
- fix: 把 FP16/BF16 的位宽做成前置小表，“多 3 位”改为“比 BF16 多 3 位尾数”；eager 改为“即时执行（写一行算一行，不预先建整图）”；首次出现处加行内注释：通道=权重矩阵的一个输入维度（一列），动态范围=最大可表示值与最小可表示值之比（或数据 max/min），离群值=远大于其余数值的少数值，校准数据=一小批代表性输入，用来统计 min/max 或激活幅值。
