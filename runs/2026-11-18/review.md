# 审校记录 · 2026-11-18 · 训练 · 第 19 课

- 归档文件：`课程/训练/2026-11-18-post-training.md`

## verdict

revise

## summary

讲义骨架完整、缝合意识好（预训练/上一课/SFT/RLHF 四段串得起来），但作为「基础较弱工程师」的教材有 3 处必须改的硬伤：①「忘了 mask 会怎样」的因果解释写错了，并与 packing 边界错位混为一谈（这是全课标题所在的核心点）；② 每步算力的 68.8 s 存在 8 倍口径错误（400 TFLOPS 没说单卡还是整机），worked example 一算就对不上；③ PPO 显存账把 rollout 与 update 两个阶段的每卡占用混成一个 24.5 GB，KV cache 又把全量当每卡，导致「没余量」的结论与数字矛盾。另有 5 处中等问题：数量级口径（3–4 vs 4–5）、position id 自相矛盾、术语未解释（σ/MFU/RoPE/GQA）、缺课后自测与解析、步数口径（3815 vs 7820）未交代假设。建议 revise 后再发。

## issues

### 1. [high] 「忘了 mask」的因果讲错，并与 packing 错位混为一谈

- **claim**：「忘了 mask，K = 2000 而不是 1200：四成位置在教模型『预测用户会问什么』。到下一轮，u2 紧跟在 a1 后面，模型学到的就是『回答完该接用户提问』——把问题当回答。」（术语卡「串味」、误区三同）
- **问题**：因果讲错了。忘 mask 的真实后果是：模型同时被训练去建模用户轮，于是学会「替用户说话/自己提问」（推理时抢话、自问自答），且回答位梯度被稀释（分母 2000 而非 1200）。「上一轮问题被当成下一轮回答」是 packing/多轮拼接时 label 与 input 错位一格才会出现的现象，与「不 mask prompt」是两种不同故障。现在正文、术语卡、误区三处用同一套混淆叙述，读者会把两个故障当成一个，排障时会查错方向。
- **建议**：把两种故障拆开写：①不 mask prompt → 学习目标包含用户轮（症状：抢话、扮演用户、复读问题），且 answer 位权重被稀释；②packing 边界错位一格 → 前一包最后一个 token 的 logits 去预测下一包首 token（这才是「串味」），修法是把每条样本首 token 的 label 置 -100。术语卡「串味」只保留②的定义。

### 2. [high] 每步算力的 68.8 s 有 8 倍口径错误

- **claim**：「每步计算 = 262,144 × 6 × 7e9 = 1.1e16 FLOP = 11 PFLOP，按 160 TFLOPS（400 × MFU 40%）要 68.8 s」。
- **问题**：400 TFLOPS 没说是单卡还是整机峰值。若按单卡（910B bf16 约 400 TFLOPS 的量级），8 卡聚合 = 8 × 400 × 40% = 1280 TFLOPS，每步应是 1.1e16 ÷ 1.28e15 ≈ 8.6 s，文中数字大了 8 倍；反推「160 TFLOPS 整机」等于单卡 20 TFLOPS，与该硬件量级不符。连带 7820 步 × 68.8 s ≈ 6.2 天/epoch，与「SFT 比预训练轻得多」的结论相反。另外 MFU 全文没有定义。
- **建议**：写明口径：「单卡 bf16 峰值 400 TFLOPS × MFU 40% × 8 卡 = 1280 TFLOPS，每步 ≈ 8.6 s」，并同步把通信占比从 0.09% 改为 62.5 ms ÷ 8.6 s ≈ 0.7%（结论「通信可忽略」不变）；首次出现 MFU 时给一句白话（硬件峰值里真正用于有效计算的百分比）。

### 3. [high] PPO 显存账把两个阶段混成一个数，KV cache 又按全量记

- **claim**：「196 GB，8 卡平摊 24.5 GB/卡，四份都得分片才装得下。但采样时策略必须整份或按 TP 切开，不能零散分片」「PPO 每卡 24.5 + 4.3 GB 再加激活，能跑但没余量」。
- **问题**：三个数字互相打架：①24.5 GB/卡 的前提是四份模型全切分，可紧接着又说 rollout 时策略不能零散分片——这两个阶段的每卡占用不是同一个数，文中却当成一个数继续往下加；②KV cache 的 4.3 GB 是 32×1024 token 的全量，TP=8 时每卡实际约 0.54 GB，按每卡 4.3 GB 加高估了 8 倍；③24.5 + 4.3 = 28.8 GB，在 64 GB 卡上还余 35 GB，「没余量」与自己的数字矛盾。
- **建议**：分两阶段列账：rollout 阶段（策略/ref/RM 各按 TP=8 切到 1.75 GB，KV 0.54 GB/卡，加激活）；update 阶段（ZeRO-2 的 22.75 GB/卡 + 激活）。给出每卡峰值 = max(两阶段) 再下「有没有余量」的结论，并注明 KV cache、参考模型、奖励模型都随 TP 切分。

### 4. [medium] 数量级口径自相矛盾（3–4 vs 4–5）

- **claim**：「几万到百万条，1e8–1e9 token，比预训练小 3–4 个数量级」。
- **问题**：与本文自己的预训练口径（10T = 1e13）算不平：1e8 差 5 个数量级、1e9 差 4 个数量级，应为 4–5 个数量级。第 1 步又写「1e13 ÷ 1e9 = 1e4，正好差 4 个数量级」，两处对同一件事给出不同区间，读者按哪个算都不一致。
- **建议**：统一写成「比 1e13 的预训练小 4–5 个数量级（1e9 差 4 阶、1e8 差 5 阶）」，或把范围收窄到 1e9 并只说 4 个数量级。

### 5. [medium] position id 重置的表述自相矛盾

- **claim**：「不重置则 RoPE 相位跨样本累加」……「也有实现靠 varlen attention 的 cu_seqlens 分块而不重置，两种都能正确分块（存疑，查你所用版本文档）」。
- **问题**：前一句刚说明跨样本累加会带错相位，后一句又把「重置」与「不重置」写成等价且都正确，自相矛盾。cu_seqlens 只解决「样本之间不可见」，解决不了位置相位问题：不重置时训练看到的位置分布（第二条从 4096 开始）与推理时（每条从 0 开始）不一致，是已知会掉效果的坑，不能当等价方案写。
- **建议**：改成：「cu_seqlens 只保证样本间互不可见；position id 必须每条样本从 0 重数，才能与推理时的位置分布对齐。部分框架/版本默认不重置，属已知坑，须在自己版本上显式检查（可打印 position_ids 验证第二条是否从 0 开始）。」

### 6. [medium] 术语未解释就用（σ/MFU/RoPE/GQA/on-policy/KL/BOS）

- **claim**：正文直接使用 σ、MFU、RoPE、GQA、cu_seqlens/varlen、在线策略（on-policy）、KL、BOS。
- **问题**：目标读者是基础较弱的工程师，但这些词都是未解释就用的：σ 从没说是 sigmoid（Bradley-Terry 卡还用它解释它）；MFU、RoPE、GQA、KV cache 在术语卡里根本没有条目；「KL 惩罚」卡用 KL 解释 KL；「在线策略更新」是 on-policy 的生硬直译，读者不知道它意味着「只能拿当前策略刚采的数据更新」。这直接卡住按步骤手算与理解「KL 为什么能拴住策略」。
- **建议**：术语卡补 MFU、RoPE、GQA、KV cache、σ(sigmoid)、on-policy 六条；正文首次出现处各加一句白话：σ(x)=1/(1+e^{-x}) 把分数差压成 0–1 的概率；MFU 见上；RoPE 是按位置旋转 Q/K 的编码方式；GQA 是多个 Q 头共享一组 KV 头；on-policy 指只能用当前策略刚采的样本更新。

### 7. [medium] 教学结构缺课后自测与答案

- **claim**：教学结构：有「课前自测 / 核心概念 / 一步一步理解 / 常见误区 / 术语卡 / 来源」，但无课后自测与任何答案。
- **问题**：结构缺「课后自测题 + 答案/解析」这一环，讲完无法自检。且 5 道课前自测有 3 道在正文找不到明确落点：Q4「奖励模型为什么不能替代人」只在机制里零散提 reward hacking，没有正面回答（RM 是有限偏好数据上的代理、分布外无定义、可被优化器钻空子）；Q1 的「为什么 prompt 段要填它」也只给了结论。读者做不出来会怀疑教材。
- **建议**：加一节「课后自测（含解析）」，3–5 题覆盖 mask 边界、packing 三边界、PPO 显存；并给课前 5 题标注答案所在小节，其中 Q4 在 RM 节补一段正面回答。

### 8. [medium] 步数口径（3815 vs 7820）未交代假设

- **claim**：「1 epoch = 1e9 ÷ 2.62e5 ≈ 3815 步」……「实际前向 token 变成 1e9 ÷ 0.488 ≈ 2.05e9，step 数 7820」。
- **问题**：3815 步隐含「每个 4096 窗口都装满真实 token」，即已经 packing、零 pad；到第 3 步又用 7820 修正，中间没交代前提变化，读者会以为两个数里有一个算错（这正是「跟着手算会卡住」的地方）。另外预训练侧「1e13 ÷ 4e6」的 4e6（每步全局 token）凭空出现，没有出处，也没与 SFT 的 2.62e5 对比。
- **建议**：在第 2 步标明「此数假设已 packing、无 pad」，并显式写出公式 steps = 真实 token ÷（卡数 × 窗口长 × 累积步数 × 利用率）；把 4e6 的来源（预训练全局 batch 约 4M token）写明，再让 3815/7820 作为「同一公式、利用率 100%/48.8%」的两个取值出现。
