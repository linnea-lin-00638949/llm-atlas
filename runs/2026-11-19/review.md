# 审校记录 · 2026-11-19 · post-training · 第 20 课

- verdict: revise
- summary: 整体结构和主线很好，DPO 推导、σ(3.4)/Δ=3.4、k3=0.307、GRPO 优势等数值例子基本正确；但有一处因果归因错误，且 k3、critic、R1、显存账、参考模型等处把简化或惯例写成了绝对事实，建议修订后再用。

## issues

### 1. severity: high

- claim: 一句话总结说「三个故障都从这长出来」，术语卡说「覆盖……是 DPO 三类故障的总根」。
- 问题: 长度偏置的机制是隐式奖励对 token 求和而非平均（讲义第三节自己也这样写），即使偏好数据覆盖充分也会出现；覆盖不足本身是第三类故障，似然位移才主要与低概率/分布外偏好对相关。把三者都归到覆盖，和本节机制矛盾，会让读者记错因果。
- 建议: 拆成三条独立机制：似然位移←偏好对落在策略低概率区；长度偏置←token 求和而非平均；覆盖不足←离线数据分布外无约束。可说「离线数据放大前两者」，不能说三者都以覆盖为总根。

### 2. severity: medium

- claim: k3 估计「逐 token 算、不靠采样、恒非负」；术语卡写「不依赖采样」。
- 问题: k3 仍然是在 π_θ 的 rollout 样本上逐 token 计算的，依赖采样；它避免的是从 π_ref 额外采样，优点是逐 token 非负、方差比 k1 低。写成「不靠采样」会让读者以为没有样本也能算 KL。
- 建议: 改为「只需 π_θ 的采样，不需从 π_ref 额外采样；逐 token 非负，方差低于 k1」，并说明它估计的是 KL(π_θ‖π_ref)。

### 3. severity: medium

- claim: 「critic 要学的是『这个 prompt 平均能拿几分』，可同一 prompt 采了 G 条，均值就是现成的基线，不用学。」
- 问题: critic 是 V(s_t)（从某个 token/前缀出发的期望回报），不是 prompt 级常数；GRPO 的组均值只是 prompt 级蒙特卡洛基线，是更粗的替代，不等价于 critic。这样写会低估 critic，也解释不了 GRPO 为什么需要 G 倍采样、方差为何可能更大。
- 建议: 说明 critic 估计逐 token/prefix 的价值；GRPO 用同组 G 条奖励的均值做 prompt 级基线，省掉逐 token 价值网络，代价是采样更多、基线更粗。

### 4. severity: medium

- claim: 「DeepSeek-R1 用『答案对不对 + 格式对不对』的规则奖励，不需要奖励模型」；来源又把 R1 GitHub 仓库标为「GRPO 训练脚本与规则奖励实现」。
- 问题: R1 的完整流程并非完全不用奖励模型：论文为通用任务用 66k 偏好对训练了奖励模型（helpfulness/harmlessness），冷启动数据里还用了生成式奖励模型；规则奖励主要覆盖数学/代码/STEM 等可验证任务，R1-Zero 的推理 RL 才是纯规则奖励。另外 deepseek-ai/DeepSeek-R1 仓库只有推理/部署代码，没有 GRPO 训练脚本，来源标注不准确。
- 建议: 限定为「在数学/代码等可验证推理任务上用规则奖励；通用任务仍需奖励模型/偏好数据」；GRPO 训练脚本改引 DeepSeekMath 或 OpenRLHF/TRL 等实际含训练代码的仓库。

### 5. severity: medium

- claim: 第 5 步「DPO 每卡 22.75 + 1.75 = 24.5 GB」；同段「GRPO 带奖励模型 24.5 GB，带规则验证器更少」；「PPO 同口径 45.5 GB」。
- 问题: 22.75 只有在 8 卡、ZeRO-2（权重 14 GB 复制、梯度+优化器 70/8=8.75）且参考模型 TP-8（14/8=1.75）时才成立，讲义没给卡数和切分假设，读者无法手算。更严重的是 GRPO 三模型 112 GB > DPO 98 GB，按同一算法应是 22.75+1.75+1.75=26.25，不会与 DPO 同为 24.5；若奖励模型单独服务，「带规则验证器更少」也不成立。PPO 的 45.5 只算策略+critic，未计参考/奖励，和 DPO 的 24.5 含参考不是同一口径。
- 建议: 明确「8 卡、ZeRO-2、参考 TP-8」，逐项写出 policy/ref/reward 的每卡占用；GRPO 带奖励模型改为 26.25（或说明奖励模型在推理侧、训练卡仍 24.5，并删掉「更少」）；PPO 注明 45.5 只含策略+critic，参考/奖励在推理侧或另计。

### 6. severity: medium

- claim: 「参考模型必须等于训练起点」；但 worked example 里 π_θ 的平均 logprob（−0.5/−0.9）已经不同于 π_ref（−0.8/−0.85），没说明这是训练中途。
- 问题: 数学上 π_ref 是 KL 锚点，标准做法是从它初始化，但不是「必须」；换参考会改变隐式奖励的零点，需要重新解释 loss，而不是绝对不能换。例子若在初始点，π_θ=π_ref，log ratio 全 0、Δ=0、L=log2≈0.693；现在直接给出已偏离的数值，初学者会问「参考不是起点吗，为什么策略 logprob 不同」。
- 建议: 把「必须」改为「通常从 π_ref 初始化（SFT 模型）」；在例子开头加一句「假设已训练若干步」，并给出初始 L=log2≈0.693 作为对照，再进入 −0.5/−0.8 的中途数值。

### 7. severity: medium

- claim: 工程与显存段落直接使用 ZeRO-2、TP、vLLM、prefix caching、prefill/decode 等术语，术语卡里没有。
- 问题: 对基础较弱的读者，「ZeRO-2 切策略、TP 切参考」和「vLLM 起服务、打开 prefix caching」是未解释的缩写/系统概念；如果前置课没有覆盖，读者会在第 5 步和工程段落卡住。RLHF、SFT 也默认已学。
- 建议: 在首次出现处加一句定义或放进术语卡：ZeRO-2（切梯度+优化器状态、权重复制）、TP（张量并行切权重）、prefix caching（复用共享 prompt 的 KV）、prefill/decode（预填充/逐 token 生成）；或明确指向第 19 课/推理模块。
