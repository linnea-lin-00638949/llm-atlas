# 审校记录 · 第 22 课 · MoE 稀疏化

- **date**: 2026-11-21
- **lesson**: 第 22 课 · MoE 稀疏化：同样算力怎么装更多参数
- **verdict**: revise

## summary

讲义结构完整、worked example 的 softmax/容量/aux loss 算术基本可复现，decode 带宽与显存换容量的工程直觉也讲得清楚。主要问题集中在「参数/算力账」的口径与 DeepSeek-V3 的数字对不上；另有 all-reduce 通信量、drop 语义、缺少课后自测题和若干未解释术语。建议按下列 high/medium 项修订后再发布。

## issues

### 1. [high]

- **claim**: 「把 FFN 复制成 N 份，总参数涨约 N 倍；每 token 只走 k 份，FLOPs 只涨 k 倍；每 FLOP 能装的参数放大约 N/k 倍」，以及「显存多花 N/k 倍，换来 N 倍专家容量」。
- **问题**: 与同段「FFN 约占参数 2/3」不自洽：若 attention 占 1/3，总参数应为 (1+2N)/3 倍（N=8 时 5.67×，不是 8×）；「FLOPs 只涨 k 倍」也只对 FFN 子层成立，全模型按同一 2/3 假设约为 (1+2k)/3 倍（k=2 时 1.67×，不是 2×），性价比约为 (1+2N)/(1+2k)（3.4×，不是 4×）。第 6 步的 8×/2× 是 FFN-only 口径，开头却是全模型口径。另外「显存多花 N/k 倍」是对同算力 dense（kP）而言，「N 倍专家容量」是对原 dense（P）而言，基准不同；「专家容量」还与后文 capacity（每专家 token 数）术语冲突。
- **建议**: 统一口径：要么在开头明确「以下倍数只看 FFN 部分」并保留 N/k，要么按全模型写 (1+2N)/(1+2k)，同步修正总参数、FLOPs、一句话总结里的倍数。把「N 倍专家容量」改为「N 倍专家参数/专家数」，并注明显存倍数的比较基准。

### 2. [high]

- **claim**: 「MoE 模型激活≈总参数×k/N（仅 FFN 部分）」，并用 DeepSeek-V3「671B 总参数、37B 激活、比值约 18」作为这套账的例子。
- **问题**: 按该公式，V3 的激活应为 671×8/256≈21B，与文中 37B 不符；V3 的 routed 配置是 256 选 8（另有 1 个共享专家），无论按 256/8=32 还是把共享算进去，都不是 18。原因是激活参数还包括全激活的 attention 和永远开启的共享专家，k/N 只对 routed FFN 成立；「仅 FFN 部分」的括注救不了这个式子，因为乘的是全模型总参数。
- **建议**: 把定义改为「激活参数 = attention（全激活）+ 共享专家 + k 个 routed 专家」，说明 k/N 只适用于 routed FFN；给 V3 一个简短分解，说明 18 是总/激活比、32 是 routed FFN 的 N/k。术语卡同步修改。

### 3. [medium]

- **claim**: 「all-reduce 每层一次、量固定；all-to-all 每个 MoE 层两次（去、回），量随 batch 涨」。
- **问题**: all-reduce 的量同样随 batch×seq（激活 B·S·d）增长，TP 下每层通常不止 1 次（常见 2 次）；真正的差别是每 token 通信量 O(d) 对 O(k·d)，以及 all-to-all 是多对多、固定开销更多，而不是「固定 vs 随 batch 涨」。这个说法会让读者低估 decode 大 batch 下的 all-reduce 成本。
- **建议**: 改成「每 token all-reduce 约 d 个元素、all-to-all 约 k·d 个元素，两者都随 token 数线性增长；all-to-all 还是多对多且固定开销更大」，保留「all-to-all 是 EP 新瓶颈」的结论。

### 4. [medium]

- **claim**: 「训练时被 drop 的 token 在这一层没有梯度；推理时它只由剩余专家以残缺权重合成，输出幅度变小、质量下降」。
- **问题**: drop 是按专家发生的：第 4 步的 t3 只丢了 e1、仍走 e4，仍有梯度经 e4 和 router 回传；只有 k 个专家全丢时输出才为 0、才近似「整层无梯度」。另外「推理时 drop」也不是主流推理引擎（vLLM 等）的行为，它们不做训练期的容量截断；写成普遍事实会误导部署。
- **建议**: 区分「该专家上的梯度为 0」与「token 整层无梯度」；把推理句限定为「若推理也施加容量限制，才会出现残缺权重合成」，并补一句训练/推理的差异。

### 5. [medium]

- **claim**: 结构清单要求「课前自测、核心概念、例子、误区、自测题、术语卡、来源」齐全。
- **问题**: 讲义只有课前自测（且没有参考答案），完全没有课后自测题；课前 Q2「单 token 延迟变几倍」若按相对原 dense 的口径是 2×（要读 2 个专家），不是 1×，讲义没有给答案，容易被读成「只激活 2 份所以延迟不变」。
- **建议**: 补 5–6 道课后自测题+答案，覆盖 N/k 账、capacity/drop、aux loss、EP 通信、decode 带宽；给课前自测加简要答案或提示。

### 6. [medium]

- **claim**: 「走 softmax 的雅可比」「惩罚 logits 的 log-sum-exp 平方」；router 形状用 d_model，第 6 步用 d、d_ff。
- **问题**: 雅可比、log-sum-exp 没有解释，d_model/d_ff 没有定义；对基础较弱的读者，正好卡在 router 机制和 z-loss 两个关键处。
- **建议**: 各加一句解释：雅可比=softmax 各输出对 logits 的偏导组成的矩阵；log-sum-exp=log(Σe^{z_i})；d_model=隐层维度、d_ff=FFN 中间维度；或补进术语卡。

### 7. [low]

- **claim**: 「FFN（前馈网络，上一课 SwiGLU 那一块）」与「上一课说『数据决定能力分布』」。
- **问题**: 两处「上一课」指代冲突；若上一课是数据课，SwiGLU/FFN 应在更早模块，本课在依赖未确认的前置。另外本课默认读者会 softmax 求导与梯度反传，也需要核对。
- **建议**: 改准指代（写明具体课号），开头加一行前置清单/回顾；若前置未讲，补最小回顾（softmax 求导、梯度反传各一句即可）。

### 8. [low]

- **claim**: 「f、P 都均匀时取最小值（乘 N 后恰为 1）」；「当前值比下限高 28%」。
- **问题**: 均匀时 N·ΣfP 确实等于 1，但 1 不是严格下界：可构造反例 N=2，90% token 的 gate≈(0.5001,0.4999)、10% 为 (0,1)，则 f=(0.9,0.1)、P≈(0.450,0.550)，N·ΣfP≈0.92<1。把它叫「下限」并说「高 28%」不严谨。
- **建议**: 把 1.0 改称「均匀参考值」，说「比均匀参考值高 28%」；或只保留「越接近 1 越均衡」的说法。
