# 第 4 轮串讲 · 2026-11-06

> 本轮四课：第 13 课《Prefill/Decode 分离与长上下文》、第 14 课《推理成本与调度》、第 15 课《预训练在学什么：从下一个 token 到 scaling law（上）》、第 16 课《从 1B 到 7B：显存四笔账、数据配比与 loss 曲线实战（下）》。
>
> 前两课在推理侧（怎么快、花多少钱），后两课在训练侧（能力怎么来、怎么训得动）。这一轮把它们接成一条线：**训练定下的数字，就是推理的天花板；推理挣回的钱，决定训练该怎么花。**

## 一张图串起来

主线一句话：**训练定 N 与 D → 显存账逼出分布式 → 推理端 prefill/decode 分家 → 换算成 $/token**。

```
【训练侧：能力从哪来】                【推理侧：token 怎么出去】           【经营：值多少钱】
L15 目标 + scaling law               L13 prefill 吃算力 / decode 吃带宽    L14 成本与调度
L(N,D)=E+A/N^α+B/D^β                 KV∝S、prefill∝S²、传输∝S            $/token = 时价 ÷ 有效吞吐 ÷ 利用率
      │ 定下 N、D                          │ 拆成 P 池与 D 池                    │ 定 SLO 与报价
      ▼                                    ▼                                    ▼
L16 显存四笔账 16 B/参数              KV 传输 = 大小 ÷ 有效带宽            SLO → 并发上限 → 定价
7B = 112 GB → ZeRO 切状态            长上下文既最该分离也最难分离          敢拒绝才守得住 goodput
```

三个数字就是链子的接头，全部从「参数 N」长出来：

1. **16 B/参数**（L16）——训练时每个参数要占的字节：权重 2 + 梯度 2 + Adam m/v 各 4 + fp32 主权重 4。7B × 16 B = 112 GB，与一张 64 GB 卡差 48 GB；加上激活（重算后 1.6 GB）与约 2 GB 碎片，到约 116 GB，才差 52 GB——这就是必须切状态（ZeRO）、必须多机的全部动机。
2. **2N 字节**（L15）——推理时每吐一个 token 至少要把权重读一遍，14 GB ÷ 3 TB/s（整机/聚合的有效带宽，TP 后；单卡按 1.6 TB/s，见 L13）≈ 4.7 ms → 单流约 214 token/s。加 batch 是把这一次读摊给 B 个请求，上限才抬到「有效 FLOPS ÷ 2N」。
3. **6ND**（L15）——训练总算力，7B/140B token ≈ 5.9×10²¹ FLOP，8 卡 53 天。D 提到 15T 就是 15.5 年。

还有一条**回环**，别漏掉：L14 的 $/token 会回头修改另外三课的选择。推理服务几十亿次请求时，参数每多一份就多付一份，所以业界故意超配数据（Llama 3 的 8B 用了 15T token），这叫「推理最优」而不是「训练最优」——L15 的 20 token/参数是训练侧好用的经验点，不是严格最优、也不是该停的地方。

## 综合自测

### 1. 7B 模型单流 decode 只有约 214 token/s，为什么线上能压到整机 1,500 token/s？这 1,500 又对应多少路并发、多少 TPOT？
<details><summary>查看答案</summary>214 token/s 是带宽口径的单流上限：每吐一个 token 都要把 14 GB 权重读一遍，14 ÷ 3 TB/s（整机/聚合的有效带宽；单卡按 1.6 TB/s）≈ 4.7 ms。L15 的 2N 还给算力口径的上限：160 TFLOPS ÷ 2N ≈ 单卡 1.1 万 token/s。加 batch 后权重每步仍只读一次，却摊给 B 个请求，8 卡 TP + 连续批处理后整机吞吐能远高于 214。但 **1,500 token/s 不是从 2N 推出来的**——它是 **L14 压测给出的 SLO 吞吐（输入）**：TPOT ≤ 50 ms ⇒ 每路每秒 20 token ⇒ 1,500 ÷ 20 = 75 路，正好用来校验 `--max-num-seqs`。要分清三个数：单流上限（带宽 ÷ 2N，约 214，由 N 定死）、整机吞吐（batch 与并行决定，1,500 是压测目标）、每路延迟（TPOT，由带宽与 KV 长度决定）；三者不是同一个东西，也不能互相推导。</details>

### 2. 同样 10 请求/秒，输入 8K/输出 500 与输入 512/输出 500，P:D 为什么从 2.6:1 变成 1:1？
<details><summary>查看答案</summary>看两段的「工作量 ÷ 单卡能力」。P 侧工作量 = 到达率 × 单请求 prefill 时间：8K 时按 1.1 s 算，10 × 1.1 = 11 卡（加 15% 余量 13 张）；512 token 只要 0.055 s，10 × 0.055 = 0.55 卡 → 1 张。D 侧工作量 = 输出 token 速率：两者都是 5,000 token/s，但短上下文时每步读的 KV 少得多（约 126 MiB/请求），批可以开到 128 甚至 300，单卡吞吐从 1,067 涨到 6,400 token/s，于是 5,000 ÷ 6,400 < 1 卡。所以 P:D 只由**长度分布**决定，抄别人的配比一定错。这也解释了长上下文为什么最值得分离：P 侧阻塞随 S² 放大，D 侧随 S 变慢又更怕被打断。</details>

### 3. 上下文从 8K 涨到 128K，把显存、配比、传输、成本四笔账连起来算一遍。
<details><summary>查看答案</summary>① 显存：128 KiB/token，8K = 1 GiB，128K = 16 GiB；40 GB KV 预算下并发从 40 条掉到 2 条，掉约 20 倍。② 计算：prefill 的注意力项 4·层数·S²·d_model 在 128K 处约是线性项的 4.3 倍（8K 时只占 21%），所以 P 侧工作量暴涨，P:D 必须重算。③ 传输：16 GiB 在 200 Gbps 上 690 ms、25 Gbps 上 5.5 s，而 TTFT 的 SLO 可能只有 2 s——网络成了硬门槛，必须高速互联 + 逐层重叠。④ 成本：并发掉 20 倍意味着同样的卡只卖出很少的 token，分母塌了，$/token 会成倍上升；同时 128K 请求的输入 token 数是 16 倍，若输入计价 1.48 元/百万，单请求输入成本就是 8K 的 16 倍。结论：长上下文是「显存、延迟、成本」三个维度同时恶化，不是一个参数能救的。</details>

### 4. 有人问：把 7B 的训练数据从 140B 加到 15T，训练变慢 100 倍值不值？
<details><summary>查看答案</summary>先算账：C = 6ND，D 涨 107 倍，训练时间从 53 天变成约 15.5 年（8 卡单机），所以这个决定根本不是在单机上做的，必须多机。再问值不值：20 token/参数是 Chinchilla 实测的经验点、训练侧的好起点，不是严格最优；严格解 D/N 随算力缓升（∝ C^0.097，Chinchilla 处约 93），但 loss 面在 N–D 方向极平（32B/3T 与 70B/1.4T 只差 0.006），所以 20 好用；而超配数据是**推理**最优。超配数据换的是「同样 loss 下参数更少、推理更便宜」。判据要用 L14 的口径：模型要服务几十亿次请求时，单请求成本大致 ∝ N，N 减半就把 $/token 砍半；反之若只做少量离线任务，训练省下的钱更重要。一句话：**训练最优看 6ND，推理最优看 2N**，两边算完再决定。</details>

### 5. 为什么「7B 只要 14 GB，64 GB 卡随便训」这句话错得离谱？把训练账和推理账并排放。
<details><summary>查看答案</summary>14 GB 是 bf16 的**推理权重**，连 KV cache 都还没算。训练是另一本账：权重 2 + 梯度 2 + Adam m/v 各 4（fp32）+ fp32 主权重 4 = 16 B/参数 = 112 GB，再加激活（重算后 1.6 GB）与碎片约 116 GB，单卡差 52 GB，占 64 GB 的 181%。同一个 N，两本账差 8 倍。引申两条：① 推理侧装得下不等于跑得好——40 GB KV 预算只够 2 条 128K 请求；② 训练侧装不下时先分清哪一笔：micro-batch 减半还 OOM 才是状态问题，才轮到 ZeRO；加卡做 DP 只是复制状态，单卡一点不省。</details>

### 6. 训练时第 3 万步 loss 从 2.1 跳到 3.6、两步后回落；线上同一周 TTFT 的 P99 从 2 s 抖到 4 s。两者的处置顺序为什么是同一个套路？
<details><summary>查看答案</summary>严格说，不是「同一个套路」，而是同一条原则：**先定位坏在哪一段，再按成本从低到高动手**——步骤并不一一对应，而且要先分指标。

**线上先分 TTFT / TPOT。** TTFT 归 P 管（排队 + prefill + KV 传输）：先查 P 侧排队是否积压、长 prompt 是否集中到达、单次 prefill 时长、KV 从 P 传到 D 是否变慢。长 prefill 撞进 decode 批次，首先抬高的是**已在解码请求的 TPOT**（L13 第 6 步：30 ms → 约 1.1 s），拿它查 TTFT 会查错段。TPOT 归 D 管（批大小与带宽）：才去查 decode 批次里是否混入长 prefill、批是否被顶满、KV 读取是否被挤占。

**训练侧按条件分级，不是固定三步。** 题目是「单点跳起、两步后回落」：① 先定位并跳过该 batch——零成本，直接验证是不是这批数据的问题；不复发就记一笔，**不回滚**。② 只有连续多次跳动、或越跳越高（台阶不回来）时，才回滚 checkpoint、学习率降 20%~50%——丢几步，但会掩盖根因。③ 查数据过滤与梯度裁剪是否真生效——最贵，用于防复发。

线上同理：① 先做最便宜的定位（排队、长 prompt、批次构成）→ ② 再动 max-num-seqs / 排队预算 / chunked prefill 切块（丢一点吞吐）→ ③ 最后才加卡或上 PD 分离（最贵）。

共同原则只有一条：**最便宜的诊断先做**。一上来就回滚或扩容，会把「数据 bug」「调度 bug」变成长期的噪声和账单。</details>

### 7. 「利用率 90%，我们很省钱」和「loss 降到 1.9 了，模型很强」这两句话错在同一个地方，是哪里？
<details><summary>查看答案</summary>都把**过程指标**当成了**结果指标**。利用率 90% 是 NPU 占用率，可能来自小 batch 或跑超 SLO 的流量，成本利用率也许只有 50%，每百万 token 是 5.93 ÷ 0.5 ≈ 11.9 元而不是 6.6 元。loss 低同理：它有不可约截距 E（Chinchilla 口径 1.69，换数据或分词器就变），而且代码数学占比一升，平均 loss 天然下降——那可能只是换了一把尺子。正确的做法都是同一个动作：**换用带 SLO / 带评测的口径**。成本侧只数同时满足所有 SLO 的 goodput；能力侧要同数据同分词器对比 + 分来源 loss + 下游评测。两个词其实是同一个词——「有效」：有效吞吐进分母，有效数据量 D_eff 进配比。</details>

## 易混淆对照表

| 容易混的概念 | 区别一句话 |
| --- | --- |
| 训练 16 B/参数 vs 推理 2 B/参数 | 训练要存梯度、Adam 两本流水账和 fp32 主权重，推理只存一份权重（KV 另算），差 8 倍。 |
| NPU 占用率 vs 成本利用率 | 前者是卡在忙，后者是「满足 SLO 的有效产出 ÷ 满载产出」，batch 小或超 SLO 时两者能差一倍。 |
| 吞吐 vs goodput | 吞吐是吐了多少 token，goodput 是「同时满足所有 SLO」的请求数，只有后者能换钱。 |
| TTFT vs TPOT | TTFT 归 P 管（排队 + prefill + KV 传输），TPOT 归 D 管（批大小与带宽），PD 分离就是把这两条 SLO 解耦。 |
| prefill 瓶颈 vs decode 瓶颈 | prefill 是算力密集型（矩阵单元跑满），decode 是带宽密集型（27 ms 在等数据），给 decode 加算力几乎无效。 |
| 毛利率 vs 加价率 | 报价 = 成本 ÷ 利用率 ÷ (1 − 毛利率)；写成「成本 × (1 + 28%)」只是加价率，真实毛利率才 21.8%。 |
| 交叉熵 loss vs 困惑度 | 同一个信息的两种尺子，PPL = e^L；loss 是对数尺度，降 0.1 在任何位置都降 9.5%。 |
| α/β 指数 vs 20 token/参数 | 指数决定幂律形状；20 是 Chinchilla 实测的经验点、训练侧好起点，不是严格最优；严格解 D/N ∝ C^0.097 会随算力涨，只是 loss 面太平所以 20 好用。 |
| 名义配比 vs 有效配比 | 名义是读进来多少 token，D_eff 才是贡献的新信息；4 个 epoch 只值 3.72U（打 7% 折），天花板 16 倍唯一数据。 |
| spike 单点回轨 vs 台阶 | 单点跳起几十步回轨多为坏 batch，跳过即可；抬高一层不回来才是参数被踢出好区域，要回滚降 lr。 |
| z-loss vs qk-norm | z-loss 守输出层 logits 的 logsumexp 漂移，qk-norm 守 attention logits 的尺度，attention 炸了调 z-loss 调一年也没用。 |
| KV 传输是收益还是代价 | 是代价：它买的是 P/D 独立扩缩容与独立延迟控制，传输时间本身算在 TTFT 里，链路慢就白忙。 |

## 自查问题

1. 不看笔记，能不能一分钟内从「7B、140B token」用 6ND 推出「5.9×10²¹ FLOP、8 卡 53 天」，再用 L14 的 1,500 token/s 与 60% 利用率算出「每百万 9.88 元」？推不动就回看 **L15 的 6ND**、**L16 第 5 步** 与 **L14 第 3、7 步**。
2. 为什么给 decode 加算力几乎没用，加带宽接近线性提速？如果只会背这句话而算不出「算力只花 3 ms、其余 27 ms 在等数据」，回看 **L13 第 5 步**。
3. 能不能说清 D_eff 公式里 R 是「epoch − 1」而不是 epoch 数？代错一次会算出「单遍近 2U」的荒谬结果，回看 **L16「质量与重复」**。
