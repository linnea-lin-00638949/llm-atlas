# 第 11 课 · 量化与编译基础

> 学完今天，你能：

> 2. 区分 PTQ 与 QAT：要不要训练、多少数据、何时必须上 QAT
> 3. 说清 AWQ / GPTQ / SmoothQuant 各治哪种误差，以及算子融合为何加速

## 课前自测

1. 70 亿参数、权重 FP16（每数 2 字节），大约占多少显存？
2. prefill 算力密集、decode 带宽密集——decode 时加速器大部分时间在等什么？

## 为什么需要它

推理的优化空间大致四类：模型、硬件、数值精度、执行与调度。量化动精度，编译动执行方式，投机解码属于第四类。

decode 每生成一个 token 都要把全部权重读一遍（KV cache 只省历史 K/V 重算，不省权重重读）。7B 模型 FP16 权重 14 GB，在 HBM（高带宽显存）带宽约 1.6 TB/s 的加速器上（按昇腾 910B 级估算，以规格为准）（存疑）：14 ÷ 1600 ≈ 8.75 ms，单请求上限约 114 token/s，还没算 KV cache 与 kernel（加速器上的一段程序）开销。压到 INT8 字节减半，上限约 228 token/s——decode 里省显存与加速是同一件事：瓶颈在搬字节。

编译治另一类浪费：算子小到只剩启动与往返时，启动比计算还贵。

## 核心概念

### FP16 / BF16

**定义**：16 位浮点，位宽 = 1 符号 + 指数 + 尾数：FP16 是 5+10，BF16 是 8+7。

**直觉**：浮点是科学计数法，指数位定「能表示多大的数」，尾数位定「能表示多细」。

**机制**：FP16 比 BF16 多 3 位尾数，相对精度约 2⁻¹¹ ≈ 5×10⁻⁴，但指数仅 5 位、上限 65504，梯度稍大就溢出成 inf；BF16 指数同 FP32、精度约 0.4%，训练稳、推理够用。两者都比 FP32 省一半显存与带宽。

**例子**：attention logits 或 loss scale 超过 65504，FP16 变 inf，BF16 不会。

### FP8

**定义**：8 位浮点，常见 E4M3（4 指数 3 尾数，精度优先）与 E5M2（范围优先）。

**直觉**：位宽再砍一半，靠缩放因子把数值挪进窄区间。

**机制**：「统计缩放 → 量化 → 反缩放」。它保留指数、逐元素对数刻度，动态范围（最大与最小可表示值之比）优于 INT8，对离群值（远大于其余数值的少数值）通常更宽容。但 E4M3 只到约 ±448、尾数 3 位（相对精度约 6%），必须按张量或按块缩放把数值挪进范围，靠缩放而非「天生抗离群」。昇腾各型号 FP8 支持不同（存疑），落地前查文档。

**例子**：W8A8-FP8 常不必再配 SmoothQuant。

### INT8 / INT4

**定义**：8 位、4 位定点整数；对称量化时 q ∈ [−127, 127]（−128 不用）与 q ∈ [−7, 7]。

**直觉**：浮点是刻度不均的尺子，整数是刻度均匀的尺子——便宜、快，但只覆盖一段区间。

**机制**：q = round(x/s) + z，x̂ = (q − z)·s。INT8 有整数点积单元、累加用 INT32，吞吐常约 FP16 的 2×（部分架构 4×）；INT4 几乎只做 weight-only（只压权重、激活仍 FP16）：权重能离线量化，激活压 4 位误差太大。

**例子**：7B 权重 14 GB → INT8 7 GB → INT4 3.5 GB，省下的可换更长 KV cache。

### 对称量化 / 非对称量化

**定义**：对称强制 z = 0，s = max|x| / 127；非对称用真实区间 [min, max]，按 uint8 存 q ∈ [0, 255]，s = (max − min)/255，z = round(−min/s)。（要 int8 就令 q' = q − 128、z' = z − 128，等价；本课用 uint8 口径。）

**直觉**：权重以 0 为中心、近似对称，不浪费码点；激活经 ReLU 后全非负，只有非对称能铺满 [0, max]。

**机制**：对称省掉矩阵乘里的零填充项，硬件友好；非对称多一个零点，更准但多一次减法。都是线性量化。

**例子**：权重用对称、激活用非对称，是常见搭配。

### AWQ（激活感知权重量化）

**定义**：Activation-aware Weight Quantization，PTQ（训练后量化）方法，权重 4 位、激活 FP16。

**直觉**：少数显著权重对应的输入通道（通道 = 权重矩阵的一列）激活幅值极大，误差被放大；保护这一小撮（约 0.1%–1%）即可。

**机制**：用校准数据（一小批代表性输入）统计每个通道的激活幅值，给权重按通道乘缩放系数 s（显著通道放大，相对误差就小），推理时把 s 折进前一层输出，等价、零开销；再叠加分组量化。

**例子**：同为 4 位，逐通道缩放 + group 128 比朴素 round-to-nearest 的困惑度劣化通常小一个量级。

### GPTQ

**定义**：用近似二阶信息、逐层求解的 PTQ，常用 3–4 位权重量化。

**直觉**：量化一个权重会产生误差，能否让后面还没量化的权重微调一下补回来？

**机制**：把一层写成最小化 ‖WX − ŴX‖²，用校准数据算 Hessian（二阶偏导矩阵，H = 2XXᵀ），取逆衡量「改哪个权重代价最小」；逐列量化，第 j 列量化后用 H⁻¹ 把误差分摊给剩余列，一次性完成、无需反向传播。

**例子**：开销集中在几百条样本的前向与 H⁻¹，产出就是普通权重。

### SmoothQuant

**定义**：把激活的量化难度搬一部分给权重，实现 W8A8（权重与激活都 8 位）。

**直觉**：激活里少量极大离群值把 INT8 刻度撑爆、其余数值被压成 0；权重较平滑，让它分担动态范围。

**机制**：用线性 Y = XW = (X/s)(sW)，s 按输入通道取 s_j = max|X_j|^α / max|W_j|^(1−α)，α 常取 0.5；离线把 s 折进权重，推理时激活先除 s 再量化，不增加矩阵乘。

**例子**：比别的通道大几十倍的那几列激活，就是被搬走的对象。

### torch.compile

**定义**：PyTorch 2.x 的编译入口，把模型从 eager（即时执行：写一行算一行，不预建整图）编译成优化后的 kernel。

**直觉**：eager 像每做一步重新叫一次外卖；编译先把整份菜单看完，合成一个订单。

**机制**：TorchDynamo 抓字节码切成 FX 图（PyTorch 的中间表示），遇到不支持的写法就 graph break（切回 eager，收益被削弱）；AOTAutograd 取前反向图，Inductor 生成 Triton（OpenAI 的 kernel 语言）或专用后端 kernel。收益来自算子融合、消除中间张量、减少 Python 开销；代价是首次编译耗时，形状变化让 guard 失效重编。

**例子**：一串小算子 eager 要两次启动 + 中间张量写回 HBM，融合后一个 kernel。

### 图优化 / 算子融合

**定义**：在计算图上做等价变换，减少算子数量与显存往返。

**直觉**：每切一样菜就洗一次锅、端一次盘子；融合就是「一锅出」。

**机制**：常见有算子融合（LayerNorm + 残差 + 量化）、常量折叠、死代码消除。加速来自：少启动 kernel（几微秒一次，小算子多时致命）；中间结果留在片上、不写回 HBM（省带宽，decode 卡带宽）。

**例子**：LayerNorm + 残差 + 量化合成一个 kernel。

### PTQ vs QAT

**定义**：PTQ 在训练完成后定量化参数；QAT（量化感知训练）在训练中就把量化误差模拟进去。

| 维度 | PTQ | QAT |
| --- | --- | --- |
| 训练 | 不需要，只跑校准前向 | 微调几百到几千步 |
| 数据 / 耗时 | 几百条样本，分钟～几小时 | 千级～万级样本，小时～数天 |
| 精度 | 8 位够用，4 位权重靠 AWQ/GPTQ 接近无损 | 更高，激活也压低位时差距明显 |
| 边界 | 难做 W4A4 | 能做 W4A4 与极低位宽 |

**机制**：PTQ 只跑前向：几百条样本统计权重与激活的 min/max 或 99.9% 分位，定出 s、z（FP8 是 scale）；AWQ/GPTQ 再据此算通道幅值与 Hessian。QAT 在前向插伪量化节点（fake quant：先量化再反量化，模拟误差但计算仍是浮点），反向时它不可导，用直通估计器（STE）把梯度原样传过去，模型便学会把重要信息放到抗量化的位置。

**例子**：4 位 PTQ 几小时出结果，掉点明显才上 QAT。

**路径**：先 PTQ → 自评测集对齐 → 掉点不可接受且位宽不能再放宽，再上 QAT。

## 一步一步理解

6 个权重做对称 INT8 量化再算点积：W = [0.12, −0.45, 0.83, −1.24, 0.02, 0.67]，X = [0.9, −2.0, 0.5, −1.5, 0.25, 0.75]。

**第 1 步 定标与量化**：max|W| = 1.24（第 4 个权重），s = 1.24/127 = 0.0097638；q = round(w/s) = [12, −46, 85, −127, 2, 69]（0.12 → 12.29，−0.45 → −46.09，0.83 → 85.01，0.02 → 2.05，0.67 → 68.62）。

**第 2 步 反量化** x̂ = q·s：12s = 0.1172（−0.0028）；−46s = −0.4491（+0.0009）；85s = 0.8299（−0.0001）；−127s = −1.2400（0）；2s = 0.0195（−0.0005）；69s = 0.6737（+0.0037）。最大绝对误差 0.0037，占满量程 1.24 的 0.30%。

**第 3 步 激活也量化**：max|X| = 2.0，s_x = 2.0/127 = 0.015748；q_x = [57, −127, 32, −95, 16, 48]，x̂ = [0.8976, −2.0000, 0.5039, −1.4961, 0.2520, 0.7559]。粒度是绝对的：0.5、0.25、0.75 都被放大 0.79%，−2.0 恰好整除、误差为 0。

**第 4 步 整数累加**：57·12 + (−127)(−46) + 32·85 + (−95)(−127) + 16·2 + 48·69 = 684 + 5842 + 2720 + 12065 + 32 + 3312 = 24655。

**第 5 步 反量化结果**：24655 · s · s_x = 24655 × 1.5376×10⁻⁴ ≈ 3.7910；真值 = 0.108 + 0.900 + 0.415 + 1.860 + 0.005 + 0.503 = 3.7905。整条链路没有一次浮点乘加，只有整数乘加 + 最后一次缩放——量化 kernel 快的原因。

**第 6 步 拆开看误差**：只量化权重 X·ŵ = 3.7888（−0.04%）；只量化激活 x̂·W = 3.7926（+0.06%）；两者都量化 3.7910（+0.01%）。逐元素看，权重最大误差 0.30%、激活 0.79%；总和只错 0.01% 是方向相抵的巧合，不可外推。

**第 7 步 分组与收益**：每 128 个权重共享一个 s，组内动态范围变小、刻度更细，误差常降一个量级；代价是每组多一个 scale——4 位下 64 字节 + 2 字节 ≈ 3.1%，8 位下 128 字节 + 2 字节 ≈ 1.6%。收益上 7B：FP16 14 GB → INT8 7 GB → INT4 3.5 GB，上限与字节数成反比，约 2×、4×；但 INT4 权重要先反量化成 FP16 才能进矩阵乘，转换耗时间，实测常明显低于 4×。

## 常见误区

**误区 1：量化了一定更快。** 省显存确定，变快不一定。decode、小 batch 卡带宽，权重量化见效；prefill 或大 batch 卡算力，weight-only INT4 还要现场反量化，可能更慢。看你更在意 TTFT（首 token 延迟）还是 TPOT（每 token 输出时间）。

**误区 2：INT4 一定不如 INT8。** 位宽低误差确实大，但 AWQ/GPTQ 加分组能把 4 位做到接近无损；4 位还能塞更大模型或更长 KV cache。要比就按自评测集比。

**误区 3：torch.compile 会改变模型输出。** 它做等价变换，数学上应一致，但浮点加法重排有末位差异；graph break 与动态形状还会造成「编译了没生效」或反复重编译，看起来变慢。上线前固定形状范围并做数值对齐。

## 一句话总结

量化「用更少的字节表示同样的数」，赢在带宽；编译「用更少的往返算完同样的图」，赢在开销；都在治 decode 的访存浪费。

## 自测题

### 1. 13B 模型 FP16 权重、带宽约 1.6 TB/s（存疑），单请求 decode 上限多少？换 INT8 呢？prefill 为何不吃这套估算？

<details><summary>查看答案</summary>
13B × 2 B = 26 GB，26 ÷ 1.6 TB/s ≈ 16.25 ms/token → 约 61.5 token/s；INT8 权重 13 GB → 8.13 ms → 约 123 token/s，正好 2×。前提是 batch = 1、带宽吃满。prefill 一次算完整个 prompt，权重被复用算很多 token，瓶颈在算力；大 batch 下权重被共享，也转向算力。所以 weight-only 量化改善 TPOT，对 TTFT 帮助小。
</details>

### 2. W = [−0.5, 1.0, 1.5] 对称量化到 INT8 与 INT4：各写 s、q、反量化结果、最大绝对误差。

<details><summary>查看答案</summary>
INT8：s = 1.5/127 = 0.011811，q = [−42, 85, 127]，x̂ = [−0.4961, 1.0039, 1.5000]，最大绝对误差 0.0039，占满量程 0.26%。INT4：s = 1.5/7 = 0.214286，q = [−2, 5, 7]，x̂ = [−0.4286, 1.0714, 1.5000]，最大绝对误差 0.0714，占满量程 4.8%。位宽每少 1 位、粒度翻倍，这就是 4 位要靠 AWQ/GPTQ 与分组补救的原因。
</details>

### 3. AWQ、GPTQ、SmoothQuant 各治哪种误差？哪个必须做 W8A8？何时转 QAT？

<details><summary>查看答案</summary>
AWQ 治「显著权重被量化误差放大」：按激活幅值找 0.1%–1% 的显著通道，逐通道缩放，只压权重（W4A16）。GPTQ 治「逐列误差在层内累积」：用校准数据算 Hessian 逆，量化一列后把误差分摊给剩余列，也只压权重。SmoothQuant 治「激活离群值撑爆 INT8 刻度」：用 Y = (X/s)(sW) 把激活范围搬一部分给权重，做 W8A8。转 QAT：PTQ 掉点不可接受、位宽不能再放宽（如 W4A4）、且有训练管线与算力。
</details>

### 4. torch.compile 的加速来自哪两件事？graph break 与动态形状为什么吃掉收益？

<details><summary>查看答案</summary>
①算子融合减少 kernel 启动次数（每次几微秒）；②中间结果留在片上、不写回 HBM，省显存往返——decode 恰好卡带宽。graph break 把图切碎、回退 eager，融合范围变小；动态形状让 guard 失效、触发重编译，形状频繁变就一直在编。排查：看日志的 break 原因 → 固定形状范围 → 数值对齐。
</details>

## 术语卡

| 术语 | 解释 |
| --- | --- |
| FP16 / BF16 | 16 位浮点：FP16 = 1+5+10（精度约 5×10⁻⁴），BF16 = 1+8+7（范围同 FP32） |
| FP8 | 8 位浮点，E4M3/E5M2，范围窄（E4M3 约 ±448），必须配缩放 |
| INT8 / INT4 | 定点整数，对称 q 取 ±127、±7；INT8 累加用 INT32，吞吐约 2× FP16 |
| 对称 / 非对称量化 | 对称 z = 0、s = max\|x\|/(2^(b−1)−1)；非对称取 [min,max]、q ∈ [0,255]（uint8） |
| PTQ | 训练后量化：用少量校准数据定量化参数 |
| QAT | 量化感知训练：插伪量化节点、STE 传梯度，更贵但更准 |
| AWQ | 按激活幅值找显著通道，逐通道缩放保护，做 4 位权重量化 |
| GPTQ | 用 Hessian 逆逐列量化，误差分摊给剩余列的一次性 PTQ |
| SmoothQuant | 用 Y=(X/s)(sW) 把激活离群值难度迁给权重，实现 W8A8 |
| torch.compile | PyTorch 2.x 编译入口：Dynamo 抓图、Inductor 生成融合 kernel |
| 图优化 / 算子融合 | 图上等价变换（融合、折叠、消除），多算子合成一个 kernel |
