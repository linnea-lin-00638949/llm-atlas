# 第 22 课 · MoE 稀疏化：同样算力怎么装更多参数

> 学完今天，你能：
> 1. 手算 MoE 的容量账与算力账：分清总参数与激活参数，推出 top-k 路由下每 token 的 FLOPs ≈ k/N 倍 dense，并说清省的是算力、省不了的仍是权重显存与 decode 带宽。
> 2. 完整讲清 router 的全链路——从 hidden state 到 gate logits、top-k 选择、权重归一化、加权求和——并解释这个离散选择为什么不可微、梯度只能从被选中的专家与 gate 权重回流。
> 3. 识别路由塌缩并说出每种解法的靶点：用负载分布与 auxiliary loss 判断专家坍缩或热门专家堆积，说清容量因子 drop、噪声、细粒度专家 + 共享专家各治什么病。

## 课前自测

1. Transformer 每层参数最多的是哪一部分？FFN 的中间维一般是 hidden 的几倍？
2. softmax 在 attention 里起什么作用？只保留 top-2 再重新归一化，行为会怎么变？
3. FFN 翻 8 倍、每 token 只算其中 2 份：相对**原来的 dense 模型**，显存、算力、单 token decode 延迟各是几倍？先想清楚「相对谁」。
4. 如果 router 总把 token 送给同两个专家，会发生什么？
5. batch=1 做 decode 时，MoE 模型每步要读全部权重，还是只读用到的？

## 为什么需要它

上一课把「数据决定能力分布」讲透了：数据管喂什么。这一课回答另一个上限：同样的算力能装下多少参数。

先记账（本课设定，非实测）：dense（稠密，每 token 都过全部权重）模型里，FFN（前馈网络，参数最密的那块）约占 2/3，attention 等占 1/3。把 FFN 复制成 N 份（MoE，混合专家，Mixture of Experts），每 token 只走 k 份。**倍数统一按全模型算**：总参数 (1+2N)/3 倍，每 token FLOPs（浮点运算次数）(1+2k)/3 倍，「每 FLOP 能装的参数」(1+2N)/(1+2k) 倍。N=8、k=2 即 5.67×、1.67×、3.4×；只算 FFN 子层才是常见的 N、k、N/k 倍——很多资料用后者，先认基准。

DeepSeek-V3 是极端例子：671B 总参数、每 token 激活 37B，比值约 18；routed FFN 是 256 选 8，稀疏度 N/k=32。18 与 32 分母不同，下面拆开。代价全在工程侧：显存装 N 份、路由要通信、训练会不稳。

## 核心概念

### 一、总参数 vs 激活参数

**定义**：总参数＝权重文件里所有参数之和；激活参数＝算一个 token 时真正参与乘加的量。dense 两者相等；MoE 的激活参数＝全激活 attention ＋ 共享专家 ＋ k 个 routed 专家——k/N 只对 routed FFN 成立。

**直觉**：FFN 像一排专科门诊。dense 是每个病人（token，模型处理的最小单位）挂所有科室；MoE 只挂 k 个——其余诊室的设备（显存）一直都在，只是今天不看这个病人。

**机制**：MoE 只替换每层 FFN，attention 不动。一个专家 FFN 参数 P，N 个共 N·P；选 k 个，FFN 子层 FLOPs＝2kP 而非 2NP。

**例子**：V3 每层 256 个 routed 专家选 8，外加 1 个永远激活的共享专家（前 3 层仍是 dense）。671/37≈18 是总/激活比，256/8=32 才是 routed 稀疏度；用 671×8/256≈21B 反推激活是错的，漏了 attention 与共享专家。

**关键**：这是**用显存换容量**，不是换算力。相对同 FLOPs 的 dense（FFN 为 kP），FFN 显存是 N/k 倍；相对原始 dense（FFN 为 P），FFN 参数是 N 倍——基准不同。decode 仍是带宽题：每步耗时≈读字节数÷带宽，MoE 只把「读多少」从总参数降到激活参数，显存变大不会让单步更快。

### 二、router 全链路

**定义**：router 是形状（专家数 × d_model）的小矩阵 W_r（d_model＝隐层维度）。五步：logit（未归一化分数）＝W_r·x → gate＝softmax(logit)（压成非负、和为 1），或用逐项 sigmoid（压到 0–1 的 S 形函数）→ top-k → 归一化 wᵢ＝gᵢ/Σ_{j∈topk}g_j → y＝Σᵢwᵢ·Expertᵢ(x)。

**直觉**：分诊台给科室打分，只挂最高的 k 个，再把 k 份诊断按分数比例加权合并。

**机制（不稳定之源）**：top-k 是**离散选择**——「选第 3 个还是第 4 个」几乎处处导数为 0。梯度只有两条路：① 被选中专家的输出乘在 wᵢ 上，∂y/∂wᵢ＝Expertᵢ(x)；② gate 概率本身，经 softmax 的雅可比（Jacobian，各输出对各 logit 的偏导矩阵）回传。未选中的专家这一步无梯度，router 的「选择能力」只能被 wᵢ 间接推动。top-1（Switch Transformer）省通信、简单；top-2 及以上更稳。

### 三、容量与 drop

**定义**：capacity＝⌈T·k/N·C⌉，T 是这一步 token 数，N 专家数，C 是 capacity factor（容量系数，常用 1.0–1.5）。它是**每个专家能收多少 token**，与「模型容量」不是一回事。

**直觉**：诊室上午只发固定数量的号；号发完，后来的病人要么被退回（drop），要么转去别的诊室（overflow，溢出到次优专家）。

**机制**：C=1.0 按平均负载配号，而负载必然波动，所以一定有人被挤掉。drop **按专家**发生：token 在专家 i 上超容只丢 i 那一份，它仍可能在专家 j 上计算并回传梯度；只有 k 个专家全超容、输出为 0，才近似「这层没有梯度」。推理侧主流引擎（vLLM 等）默认不做训练期的容量截断，「推理 drop 导致残缺输出」只在额外施加容量限制时成立。dropless 用重排（按目标专家排序、一次 all-to-all 发走）加缓冲换掉固定容量，代价是负载不均时某卡空转。

### 四、负载均衡与专家坍缩

**定义**：专家坍缩＝路由塌向少数专家，其余专家拿不到训练，MoE 退化成更小的 dense 模型。

**直觉**：马太效应——开局稍受欢迎的专家 token 多、梯度多、学得更好，于是更受欢迎。

**机制**，三个工具各管一件事：

- **auxiliary loss**：Switch 的负载均衡损失＝α·N·ΣᵢfᵢPᵢ，fᵢ 是分到专家 i 的 token 占比，Pᵢ 是该专家 gate 概率在所有 token 上的均值。均匀时 N·ΣfP＝1，这是**均匀参考值**（非严格下界），越近 1 越均衡。管「分得均不均」，不管「选得对不对」。
- **router 噪声**：训练时给 logit 加高斯噪声，逼 router 探索次优专家，管「探索」。
- **z-loss**：惩罚 logits 的 log-sum-exp 平方（log-sum-exp＝log Σe^{z_i}，logits 整体幅度的平滑度量），防 softmax 饱和后 top-k 冻死，管「数值稳定」。

DeepSeekMoE 的改动：**细粒度专家**切小切多、多选几个（2 个大块换 8 个小块选 4 个），组合空间更大；**共享专家**永远激活，专装通用知识。两者把「通用/专精」拆开，减少冗余。DeepSeek-V3 更进一步改用无辅助损失：给每个专家 logit 加偏置 bᵢ，按负载定步长调（负载低就加），把均衡从 loss 挪到打分，避免干扰语言建模目标。

### 五、工程账：all-to-all 与 grouped GEMM

**定义**：专家并行（EP）把 N 个专家分到不同卡，每卡只放一部分。

**直觉**：原先所有卡算同一份 FFN、靠 all-reduce 汇总；现在 token 得去「有它专家的那张卡」上算，通信变成按目的地分发、算完收回。

**机制**：all-to-all 是每卡把去别卡的 token 发出、同时收自己该收的。两者都随 token 数线性增长，差别在每 token 的量：TP 的 all-reduce 约 d 个元素（每层不止一次，典型是 attention 后、FFN 后各一次），EP 的 all-to-all 约 k·d 个元素。all-to-all 还是多对多、固定开销更大、卡在专家计算的关键路径上，所以成了 EP 的新瓶颈。**grouped GEMM**：各专家 token 数不同，拼不成一个大矩阵乘，于是把按专家分组的小乘打包成一次 kernel（设备端算子调用）省启动开销；分组不均时最慢那组定整体——与容量 drop 是一体两面。**prefill 吃算力、decode 吃带宽**：prefill 一次几百上千 token，矩阵乘打得满，稀疏真能兑现；decode 每请求每步 1 个 token，all-to-all 固定开销摊不开（batch 越小越摊不开），MoE 收益最差。昇腾落地：vLLM 用 `--enable-expert-parallel` 开 EP，fused MoE kernel 由 vllm-ascend 换成 Ascend C 实现；哪些 kernel 已支持随版本变化，本节不下断言，以对应版本文档为准。

## 一步一步理解

玩具配置：d_model=4，N=4 个专家，k=2，一步 4 个 token，C=1.0，只算 FFN 这一层。

**第 1 步 打分与 softmax**：logits（W_r·x 的结果）如下，e³≈20.09、e¹≈2.718、e⁰=1，每行分母都是 24.81。

| token | e1 | e2 | e3 | e4 | softmax（e1,e2,e3,e4） |
| --- | --- | --- | --- | --- | --- |
| t1 | 3 | 0 | 1 | 0 | 0.810, 0.040, 0.110, 0.040 |
| t2 | 3 | 1 | 0 | 0 | 0.810, 0.110, 0.040, 0.040 |
| t3 | 3 | 0 | 0 | 1 | 0.810, 0.040, 0.040, 0.110 |
| t4 | 0 | 3 | 1 | 0 | 0.040, 0.810, 0.110, 0.040 |

**第 2 步 top-2 加归一化**：t1→e1 0.810、e3 0.110，和 0.920，归一成 [0.881, 0.119]；t2→[0.881(e1), 0.119(e2)]；t3→[0.881(e1), 0.119(e4)]；t4→[0.881(e2), 0.119(e3)]。

**第 3 步 数负载**：总分配 4×2=8 次，e1=3、e2=2、e3=2、e4=1。

**第 4 步 容量与 drop**：capacity＝⌈4×2/4×1.0⌉＝2。e1 要装 3 个却只有 2 个号，挤掉一个（假设 t3）。t3 丢了 e1 那份 0.881，只剩 0.119×Expert4(x₃)，幅度掉到约 12%（设两个专家输出量级相近），但仍从 e4 与 router 拿到梯度。改 C=1.5：capacity＝⌈3⌉＝3 全装下；可 e1 装 3 份、e4 只 1 份，这一步时长被最忙的 e1 拉成 3 份。

**第 5 步 aux loss**：f＝[0.375, 0.25, 0.25, 0.125]。P 取各专家 softmax 概率均值：P₁＝(0.810×3+0.040)/4＝0.618，P₂＝0.250，P₃＝0.075，P₄＝0.058。ΣfᵢPᵢ＝0.232+0.063+0.019+0.007＝0.321，×4＝1.28，×0.01＝0.0128；均匀参考值 0.25×4×0.01＝0.0100，当前比它高 28%，损失项会把 t3 往更空的 e4/e2 推。（top-2 下 f 按总分配次数归一，是教学口径；Switch 原文是 top-1。）

**第 6 步 参数与算力账（只看 FFN 子层）**：N=8、k=2，设 d_model=512、d_ff=2048（FFN 中间维度）、SwiGLU 三矩阵，单个专家 P＝3×512×2048≈3.15M。8 个共 25.2M，激活 2×3.15＝6.3M，比值 4＝N/k。bfloat16（2 字节）：FFN 权重 25.2M×2B≈50 MB/层，单专家 dense 版仅 6.3 MB/层——FFN 显存 8 倍、激活参数 2 倍。decode batch=1 每步读 6.3M×2B≈12.6 MB，按 800 GB/s 有效带宽≈16 µs/层，与「同激活参数的 dense」一样：那 50 MB 是显存容量账，不是每步带宽账。prefill 按算力：每 token 仅 FFN 约 2×6.3M＝12.6 MFLOP。

## 常见误区

**一、「MoE 用更少算力装下更大参数，所以推理更便宜。」** 分两段看。prefill 确实省 FLOPs；decode 是带宽题，全部专家必须常驻显存（671B bf16 约 1.34 TB），得多卡部署，再叠 router 与 all-to-all 开销。小 batch 下每 token 成本常常高于同激活参数的 dense。省算力≠省钱，也≠省延迟。

**二、「总参数越大能力越强。」** 专家只在被选中时才贡献能力。路由不准或坍缩时，多出的参数是纯显存负担。DeepSeekMoE 的结论正相反：同样激活算力下，切细专家加共享专家比堆大专家更有效。

**三、「C 调大就不会 drop，所以越大越好。」** C 大要按最坏负载预留缓冲，「预留但用不满」的显存和算力是纯浪费；drop 本身还是隐式均衡压力，去掉它反而更易坍缩。实践取 1.0–1.5，真要 dropless 就用重排加缓冲。

**四、「aux loss 能把路由调好。」** 它只保证分得均，不保证分得对，甚至可能为了均匀把 token 送给不合适的专家。分得对来自任务梯度、router 噪声的探索和足够训练量。

### 回收课前 5 问

1. FFN 占 2/3 上下，中间维通常约 4 倍 hidden（SwiGLU 取 8/3 倍、用三个矩阵，参数量相当）。
2. 把打分压成概率权重做加权求和；只留 top-2 再归一化等于砍掉长尾、权重集中到两路，更省也更窄。
3. 权重显存 8 倍，FFN 算力 2 倍，单 token decode 延迟也约 2 倍——每步要读 2 份专家；只有 batch 大、算力打满时延迟才由算力决定。
4. 那两个专家过训、其余收不到梯度，MoE 退化成 2 专家的 dense，有效容量塌回 k/N。
5. 只读用到的 k 个，但全部专家权重都得驻留显存——这就是容量账与带宽账的分界。

## 一句话总结

MoE 把 FFN 复制成 N 个专家、每 token 只走 k 个：FFN 参数 N 倍、FFN 算力 k 倍，性价比全在 N/k；难的不是公式，而是 router 那个不可微的 top-k 选择——它带来负载不均、专家坍缩、容量 drop，最终在工程上表现为 all-to-all 通信与分组不均，把省下的算力在 decode 阶段又还回去一部分。

## 自测题

### 1. N/k 的账怎么算？

设 dense 模型 FFN 占参数 2/3，FFN 复制 N 份、每 token 走 k 份，求全模型总参数与每 token FLOPs 的倍数，并代入 N=8、k=2。

<details><summary>查看答案</summary>

总参数 (1+2N)/3 倍，FLOPs (1+2k)/3 倍，每 FLOP 容量 (1+2N)/(1+2k)。N=8、k=2 得 17/3≈5.67×、5/3≈1.67×、17/5=3.4×；只算 FFN 子层才是 N、k、N/k。V3 的 671B/37B≈18 是全模型总/激活比，routed 的 256/8=32 只是 FFN 稀疏度，激活参数里还有全量 attention 和共享专家，所以不能写成 671×8/256≈21B。

</details>

### 2. router 五步与梯度回流

写出 router 全链路，并说明梯度为什么只能从两条路回流。

<details><summary>查看答案</summary>

logit＝W_r·x → gate＝softmax(logit) 或 sigmoid → top-k → 归一化 wᵢ＝gᵢ/Σ_{j∈topk}g_j → y＝Σᵢwᵢ·Expertᵢ(x)。top-k 是离散选择，几乎处处导数为 0，梯度只走：① 被选中专家的输出乘 wᵢ（∂y/∂wᵢ＝Expertᵢ(x)，专家权重与 wᵢ 都更新）；② gate 概率经 softmax 雅可比回传到 W_r。未选中专家这一步无梯度，选择本身只能被 wᵢ 间接推动。

</details>

### 3. 容量、drop 与推理

T=4、k=2、N=4、C=1.0 时 capacity 是多少？t3 被 e1 挤掉后，它在这一层到底丢了什么？

<details><summary>查看答案</summary>

capacity＝⌈4×2/4×1.0⌉＝2。e1 收 3 个 token，挤掉 1 个；t3 只丢 e1 那份权重（0.881），仍在 e4 上以 0.119 计算，梯度经 e4 与 router 回传，输出幅度掉到约 12%。只有 k 个专家全超容、输出为 0，才近似「整层无梯度」。C=1.5 时 capacity＝3 全装下，但时长由最忙专家（3 份）决定。推理引擎默认不做容量截断，残缺输出只在额外施加容量限制时出现。

</details>

### 4. aux loss / 噪声 / z-loss 各治什么

三者的靶点分别是什么？为什么不能互相替代？

<details><summary>查看答案</summary>

aux loss＝α·N·ΣfᵢPᵢ，fᵢ 为分到专家 i 的 token 占比、Pᵢ 为其 gate 概率均值，均匀时 N·ΣfP＝1（均匀参考值，非严格下界，低于 1 也可能出现），管「分得均不均」；router 噪声给训练期 logit 加高斯噪声，管「探索」，防早期锁定；z-loss 惩罚 logits 的 log-sum-exp（log Σe^{z_i}）平方，管「数值稳定」，防 softmax 饱和把 top-k 冻死。三件事互不替代。

</details>

### 5. decode 带宽与 EP 通信

为什么 MoE 在 decode 阶段省不下带宽？all-to-all 和 all-reduce 的差别在哪？

<details><summary>查看答案</summary>

decode 每步每请求只处理 1 个 token，耗时≈读字节数÷带宽；MoE 把每步读的权重从总参数降到激活参数，但全部专家必须常驻显存（671B bf16≈1.34 TB），显存变大不会让单步更快，还要叠 router 与 all-to-all 开销。通信上两者都随 token 数线性涨，差别在每 token 的量（all-reduce 约 d 个元素、每层不止一次；all-to-all 约 k·d 个元素）与拓扑（多对多、固定开销大、夹在关键路径）。prefill 吃算力、decode 吃带宽，两段对 MoE 的感受完全不同。

</details>

## 术语卡

| 术语 | 解释 |
| --- | --- |
| MoE | 混合专家：每层放 N 个 FFN 副本，每个 token 只走其中 k 个。 |
| 专家 | 一个独立的 FFN 副本，参数不与其他专家共享。 |
| 总参数 | 权重文件里所有参数之和；MoE 里含全部未被激活的专家。 |
| 激活参数 | 算一个 token 时参与乘加的量＝全激活 attention ＋ 共享专家 ＋ k 个 routed 专家；k/N 只对 routed FFN 成立。 |
| router | 形状（专家数 × d_model）的矩阵 W_r，把隐向量映射成每个专家的打分。 |
| gate | 路由打分经 softmax 或 sigmoid 得到的概率分布。 |
| top-k | 只保留 gate 最大的 k 个专家，其余置零；离散、不可微。 |
| 权重归一化 | 把 top-k 的 gate 概率除以它们的和，使权重和为 1。 |
| 容量 capacity | 每个专家一步最多接收的 token 数：⌈T·k/N·C⌉；与「模型容量」无关。 |
| capacity factor | 容量系数 C，给负载波动留的余量，常用 1.0–1.5。 |
| drop / overflow | 超容 token 在该专家被丢弃，或改送次优专家（可能连锁溢出）。 |
| dropless | 不丢弃：用 token 重排加缓冲区代替固定容量。 |
| 专家坍缩 | 路由塌向少数专家，其余专家得不到训练，MoE 退化成小 dense 模型。 |
| auxiliary loss | 辅助损失 α·N·ΣfᵢPᵢ，逼负载与 gate 概率都均匀；均匀时取 1。 |
| router 噪声 | 训练时给 logit 加高斯噪声，鼓励探索次优专家。 |
| z-loss | 惩罚 logits 的 log-sum-exp 平方，防 softmax 饱和与数值溢出。 |
| 细粒度专家 | 把专家切得更小更多、选更多个，增加可组合性。 |
| 共享专家 | 永远激活的少数专家，专门承载通用知识。 |
| 专家并行 | 把 N 个专家分散到多张卡，每卡只放一部分。 |
| all-to-all | 全交换：每卡把 token 按目的地发给别的卡，同时收回自己的。 |
| grouped GEMM | 分组矩阵乘：把按专家分组的小矩阵乘打包成一次 kernel 调用。 |
| prefill / decode | 前者一次性处理提示、吃算力；后者逐 token 生成、吃带宽与通信。 |
