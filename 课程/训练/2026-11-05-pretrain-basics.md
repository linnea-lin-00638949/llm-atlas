## 为什么需要它

上一课算清 1B 的账：16 字节/参数 × 10⁹ = 16 GB，一张 64 GB 卡装得下——显存只是算术题。

7B 就不是了：账从「装得下」变成「还差 52 GB」，只剩四个旋钮——切状态、缩 batch、开重算、加卡。这就是下一课分布式的全部动机。

scaling law 只说「加多少数据」，不说「加什么数据」：同样 140B token，一半网页一半代码就是两个模型——配比是唯一不花 FLOP 的杠杆。

今天不引入新公式，只把旧公式压到一张卡、一份配比、一条 loss 曲线上。

## 核心概念

### 显存四笔账：四笔 12 B，加第五笔才是 16 B

**定义**：训练显存 = 模型状态 + 激活 + 临时缓冲。与 batch 无关的四笔：权重 2 B（bf16）、梯度 2 B（bf16）、Adam 一阶矩 m 与二阶矩 v 各 4 B（fp32），共 12 B；再加 fp32 主权重 4 B，才是 **16 B/参数**——ZeRO 论文给 7.5B 标 120 GB，用的就是 16。

| 项 | 字节/参数 | 7B 合计 |
| --- | --- | --- |
| 权重（bf16） | 2 | 14 GB |
| 梯度（bf16） | 2 | 14 GB |
| Adam m（fp32） | 4 | 28 GB |
| Adam v（fp32） | 4 | 28 GB |
| fp32 主权重 | 4 | 28 GB |
| 模型状态合计 | 16 | 112 GB |

**直觉**：权重是书，梯度是反馈，m/v 是 Adam 的两本流水账，主权重是底稿：每参数一份，与 batch 无关。

**机制**：bf16 只有 8 位有效数字（2⁻⁸ ≈ 0.4%），一步更新量常只占参数的 1e-4~1e-6，直接加上去会被舍入吃掉，等于没学——所以更新在 fp32 上算完再转回。

7B：12 × 7×10⁹ = 84 GB；16 × 7×10⁹ = 112 GB，单卡 64 GB 光状态就超 75%。

**激活**不按每参数算，与「同时在算的 token 数 × 层数」成正比。7B（32 层、h=4096）、s=4096、b=1，按 Megatron 估法且不存 attention 分数（FlashAttention 类实现）：s·b·h·34 ≈ 18 GB；逐层重算（多约 30% 算力）后每层只剩 2·s·b·h，32 层约 1.1 GB。一个量级之差——micro-batch 与重算才是主旋钮。

### 数据配比：一份可解释的课程表

**定义**：配比是各来源 token 的占比；Llama 3 公开的数字大致是通用知识 50%、数学与推理 25%、代码 17%、多语 8%。

**直觉**：配比是课程表，不是营养成分表：总课时固定，一门多排一节，另一门就少一节——零和。

**机制**：代码教严格语法与长程依赖：括号缩进类型必须闭合，错一个 token 后面全错；「定义」与「使用」常隔上千 token，逼模型学长依赖。数学教分步推理：链条长、答案可验证、容易造题。网页给世界知识与流畅度，多语换跨语言迁移，性价比最低但不能为零。

挤占必然：代码 17%→30%，多出的 13 个点只能从别处扣；全扣通用它就落到 37%，世界知识与流畅度通常会掉，幅度取决于被扣部分的质量与去重。

**两个坑**：① 代码数学可预测性高、loss 天然偏低，占比一升平均 loss 就降，可能只是分布切换、换了把尺子。② 名义配比 ≠ 有效配比：一个高质量数学 token 可能值十个噪声 token，要盯分来源 loss 与分能力评测。

### 质量与重复：有效数据量的两个乘数

**定义**：D_eff 是数据实际贡献的新信息，不等于读进来的 token 数；折损来自噪声与重复。

**去重**：近似重复文档让模型把「背下来」当「学会了」：train loss 漂亮、泛化不动。工程用 MinHash（随机哈希估文档相似度）近似去重，成本远低于省下的算力。

**质量分类**：小模型给每篇文档打「教育价值」分，只留高分。FineWeb-Edu 用大模型标注约 46 万篇、训一个小分类器再过滤万亿级网页，同预算下 loss 更低；代价是有偏：偏好百科腔与长文、削掉对话口语，要用分来源评测兜住。

**重复**：D_eff = U + U·R*·(1 − e^(−R/R*))，其中 **R = D/U − 1，即 epoch 数 − 1**，单遍时 R=0、D_eff=U。取 R*=15：4 epoch（R=3）→ 3.72U，是 4U 的 93%；5 epoch（R=4）→ 4.5U；16 epoch（R=15）→ 10.5U，名义 16U、亏三成；R→∞ 饱和在 16U。天花板是 16 倍唯一数据，代码公式这类低熵数据饱和更快。

### 稳定性三件套：各守一段

**定义**：让 loss 不炸、不出 NaN 地降到底：控步长、控坏 batch、控数值范围，各守一段，越界调别处没用。

**warmup + cosine 守步长**：Adam 的 v 初值为 0，前几步有效步长被放大，warmup 用几百到几千步把学习率从 0 抬到峰值；cosine 收尾，末端降到峰值约 10%。信号：前千步 loss 抖、grad norm 出尖。失效：warmup 太短 → 早期尖刺；末端没退够 → 收尾 loss 偏高（经验上 0.02~0.05，随设置变）。

**梯度裁剪 守单个坏 batch**：全局范数超阈值就等比缩小所有梯度。信号：grad norm 周期性尖峰。失效：阈值过大（如 10）等于没开，一个乱码 batch 就把参数踢出好区域；过小（如 0.1）几乎每步被裁，等效偷调小学习率还扭曲方向。

**第三件守数值范围**，信号分别是出 inf/NaN、attention 熵骤降、logZ（logsumexp，配分函数的对数）缓慢漂移：**bf16** 守整链动态范围——fp16 只有 5 位指数，梯度 1e-8 就下溢成 0，要靠 loss scaling 放大反传再除回；**qk-norm** 守 attention logits 尺度——QKᵀ/√d 一大 softmax 就饱和成 one-hot，梯度趋 0 又极易爆；**z-loss** 在 lm_head 之后惩罚 logsumexp 漂移，管不到 attention。混记很亏：attention 炸了去调 z-loss，调一年也没用。

### loss 曲线的三种形态与处置顺序

形态一 **健康收敛**：train 与 val 双降且贴合，末端变平——平台不是故障，是信号。

形态二 **spike**：单点跳起、几十步内回轨 → 多半是坏 batch，捞出来看、跳过，不复发就记一笔；连续多次、越跳越高、回不去 → 参数被踢出好区域或数值在崩，必须动手。

形态三 **台阶与翘尾**：抬高一层不回来，常见于数据源切换、学习率被改、从 checkpoint（训练存档）恢复时优化器状态没存；完全不动多半是 bug（标签没移位、mask 写错、学习率 0、重复率 100%）；末期 val 不再降、train 仍在降（翘尾）则是过拟合或重复数据记忆化，该停或回去做重。

**处置顺序**（成本从低到高）：① **跳过该 batch**，看是否恢复——零成本，直接验证是不是这批的问题；② **回滚 checkpoint、学习率降 20%~50%**——丢几步到几小时，但会掩盖根因；③ **查数据过滤与裁剪是否真生效**（grad norm 有没有被裁、去重跑没跑）——最贵，只有它能防复发。

**平台期该不该停**看三条：① 边际斜率，每加 1T token val loss 降不到 0.005 且评测不动 → 停（经验阈值）；② train/val gap，小但离不可约损失远 → 欠拟合，加数据加参数有用；gap 扩大 → 先做重加正则；③ 单位算力收益，后训练每 FLOP 回报通常高得多。

## 一步一步理解

7B、140B token、8 张 64 GB 卡，从字节算到天。

**第 1 步 状态**。7B × 16 B = **112 GB**。112 ÷ 64 = 1.75：单卡装不下，容量之和至少要两张卡——但容量够不等于装得下，必须切开状态（ZeRO 或模型并行）；DP 加卡只是复制状态，单卡一点不省。

**第 2 步 激活**。逐层重算：公式值 32 层约 1.1 GB，工程上按 **1.6 GB** 留余量。总账 112 + 1.6 + 2（碎片与通信缓冲）≈ **116 GB**，单卡差 52 GB。

**第 3 步 切到 8 卡**。ZeRO（零冗余优化器）把状态分片，越往后越省、通信越多：

- ZeRO-1，只切优化器状态那 84 GB：14（权重）+ 14（梯度）+ 84/8 = 10.5 + 2 ≈ **40.5 GB**，余 23.5 GB。
- ZeRO-2，再切梯度：14 + 14/8 = 1.75 + 10.5 + 2 ≈ **28.3 GB**。
- ZeRO-3，再切权重：112/8 = 14 + 2 ≈ **16 GB**，但每层前向都要 all-gather（把别卡分片收过来）。

按账面，2 卡 ZeRO-3 也够：112/2 = 56 + 1.6 + 2 ≈ 60 GB，只剩 4 GB 余量、micro-batch 一点不能涨。选 8 卡是为了 batch 与吞吐，不是为了「装得下」。

**第 4 步 batch 与步数**。全局 batch 取 4.2M token = 4096 × 8 卡 × 128 步梯度累积。总步数 = 140×10⁹ ÷ 4.2×10⁶ ≈ **33,000 步**。ZeRO-1 下每卡余 23.5 GB，micro-batch 可提到 8k。

**第 5 步 时间**。C = 6ND = 6 × 7×10⁹ × 1.4×10¹¹ ≈ **5.9×10²¹ FLOP**。8 张 910B，单卡 bf16 峰值 400 TFLOPS（假设值），MFU（浮点利用率，实际算力 ÷ 峰值）40%：有效 8 × 400×10¹² × 0.4 = 1.28×10¹⁵ FLOP/s，时间 ≈ 4.6×10⁶ s ≈ **53 天**。

**第 6 步 读这三个数**。53 天、单机 8 卡，刚跑完 Chinchilla 配比。换成 Llama 3 的 15T token（15T ÷ 7B ≈ **2,140 token/参数**；常引用的 1,875 是 8B 口径），同样 8 卡要 **约 15.5 年**。「7B 训不动」不止显存，是显存、通信、时间一起把你推向多机。

**第 7 步 配比落成 token 数**。140B 按 50/25/17/8 分成 通用 70B / 数学 35B / 代码 23.8B / 多语 11.2B。若代码提到 30%、通用压到 37%，变成 **通用 51.8B / 数学 35B / 代码 42B / 多语 11.2B**——代码多 18.2B，通用少 18.2B。

## 常见误区

**一、「7B 只要 14 GB，64 GB 卡随便训。」** 14 GB 是推理权重（还没算 KV cache）；训练是 112 GB 状态加激活，差 8 倍。同一个模型，两本账。

**二、「OOM 就加卡，或者换小模型。」** 先分清是哪一笔。micro-batch 减半：OOM 消失 → 是激活，缩 batch 或开重算；仍 OOM → 是状态或碎片，才轮到切分。加卡做 DP 不减单卡占用。

**三、「配比可以逐类独立调，代码越多越好。」** 份额零和：代码涨 13 个点，通用就掉 13 个点。代码可预测性高，占比一升平均 loss 就降，容易得出「代码拉到 50% 更好」的错觉——代码评测涨了、常识掉了，那是换了个模型。

**四、「数据不够就刷 epoch，反正 4 遍内不亏。」** 4 遍（R=3）只值 3.72U，已打 7% 的折；天花板在 16 倍唯一数据，之后趋零还加速记忆化。多找 10% 新数据是线性的，刷 epoch 趋零。

**五、「spike 就回滚 checkpoint。」** 回滚是第二步。第一步永远是先定位、跳过那一批——零成本，且直接告诉你根因在数据还是在优化。上来就降学习率，会把数据 bug 变成长期噪声。

## 一句话总结

7B 在 64 GB 卡上放不下：112 GB 状态（四笔 12 B 加主权重 4 B）再加激活，这份账逼出分布式；配比是零和课程表，换的是能力分布而非总量；重复最多值 16 倍唯一数据，之后趋零；稳定性与曲线判读是一件事——先定位坏在哪一段，再按成本从低到高动手。

## 自测题

### 1. 7B 用 bf16 + Adam 训练，每参数共多少字节、合计多少 GB？

<details><summary>查看答案</summary>16 字节/参数，112 GB。权重 2 + 梯度 2 + Adam m 4 + v 4（fp32）= 四笔 12 字节 = 84 GB；再加 fp32 主权重 4 字节 = 112 GB。别与推理的 14 GB 混：那只是权重，连 KV cache 都没算。112 GB 已超单卡 64 GB 的 75%。</details>

### 2. 同一份数据训 4 个 epoch，和 4 倍全新数据训 1 个 epoch，差多少？

<details><summary>查看答案</summary>差约 7%。D_eff = U + U·R*·(1 − e^(−R/R*))，R = D/U − 1（epoch 数 − 1），R* ≈ 15。4 epoch 是 R=3：1 − e^(−0.2) ≈ 0.181，×15 ≈ 2.72，即 3.72U；4 倍新数据是 4U，只亏 7%。R 若按 epoch 数代，单遍会算出近 2U。16 epoch（R=15）→ 10.5U，名义 16U；R→∞ 饱和 16U。</details>

### 3. loss 第 3 万步从 2.1 跳到 3.6、两步后回到 2.15，第一步做什么？

<details><summary>查看答案</summary>不是回滚，是定位并跳过这一批。单点跳起、几十步内回轨是典型坏 batch：捞出来看（乱码、重复、超长），过滤掉；不复发就记一笔。只有连续多次、越跳越高、回不去，才回滚 checkpoint、学习率降 20%~50%；再往下查数据过滤与裁剪是否真生效——回滚掩盖根因。若已是平台期（每加 1T 降不到 0.005 且评测不动），该停手进后训练。</details>

### 4. 代码从 17% 提到 30%，谁被挤占？平均 loss 会怎么变？

<details><summary>查看答案</summary>零和：多出的 13 个点只能从别处扣。按 140B 算，代码 +18.2B、通用 −18.2B（70B → 51.8B），数学 35B、多语 11.2B 不动。世界知识与流畅度通常会掉，幅度取决于被扣部分的质量与去重。平均 loss 大概率降，但那是尺子变了（代码可预测性高）。要看分来源 loss 与分能力评测，接受取舍。</details>

## 术语卡

| 术语 | 解释 |
| --- | --- |
| 模型状态 | 权重、梯度、Adam m/v、fp32 主权重，共 16 字节/参数。 |
| fp32 主权重 | bf16 存不住更新量，更新在 fp32 副本上算完再转回。 |
| 激活 | 前向为反向保留的中间结果；逐层重算可用约 30% 算力换一个量级显存。 |
| ZeRO | 状态分片到各卡：1 切优化器状态、2 再切梯度、3 再切权重。 |
| 数据配比 | 各来源 token 占比；Llama 3 约 50/25/17/8。 |
| 有效数据量 | 实际贡献的新信息，受噪声与重复折损。 |
| 去重 | 删近似重复文档，防把「背下来」当「学会了」。 |
| 质量分类器 | 小模型给文档打质量分，只留高分；有偏，需分来源评测。 |
| warmup + cosine | 开头把 lr 从 0 抬到峰值，末端按余弦降到峰值的约 10%。 |
| 梯度裁剪 | 全局梯度范数超阈值就等比缩小。 |
| qk-norm | 算 attention logits 前归一化 Q、K，防 softmax 饱和。 |
| z-loss | 惩罚输出层 logsumexp，锚住 logits 的共同漂移。 |
| loss spike | loss 突跳；单点回轨多为坏 batch，连续抬升多为数值崩。 |
